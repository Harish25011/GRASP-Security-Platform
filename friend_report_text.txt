Chapter 1: Introduction and Motivation 
 
1.1 Introduction 
Enterprise networks consist of interconnected servers, endpoints, databases, and cloud systems. 
As network complexity increases, the number of exploitable vulnerabilities also grows. 
Traditional vulnerability assessment tools assign static CVSS scores to individual 
vulnerabilities, but attackers typically chain multiple vulnerabilities to reach high-value assets. 
This research proposes a graph-based attack path prediction framework that dynamically 
correlates vulnerabilities across network nodes. The system generates risk scores based on 
exploitability, asset criticality, and attack path probability, enabling proactive cybersecurity 
decision-making. 
RiskWeaver is the implementation of this framework—a sophisticated attack path prediction 
and risk assessment platform that uses graph theory, AI-driven threat simulation, and real-time 
monitoring to analyze network security posture. The platform provides: 
• 
Dynamic Attack Graph Visualization: Interactive 3D representation of network 
topology with real-time threat correlation 
• 
Multi-Factor Risk Scoring: Contextual risk assessment incorporating CVSS, asset 
criticality, exploitability, and attack cost 
• 
AI-Powered Threat Simulation: Cyber Kill Chain-based attacker simulation with 
progressive attack stages 
• 
Mitigation Analysis: What-if scenario testing to quantify security improvements 
• 
Compliance Auditing: Automated scoring against NIST 800-53, SOC2, and ISO 27001 
frameworks 
• 
Real-Time Threat Intelligence: Live threat feed integration with WebSocket-based 
monitoring 
 
1.2 Motivation 
Recent research in attack graph modeling [1], graph neural networks [4], and Bayesian risk 
modeling [5] has shown the importance of predictive cybersecurity analytics. However, 
existing approaches suffer from high computational complexity, lack of explainability, and 
limited enterprise scalability. 
The motivation of this work is to design a lightweight, explainable, and scalable framework 
suitable for real-world enterprise deployment. Key motivating factors include: 
1. Gap in Contextual Risk Assessment: Traditional CVSS scores evaluate vulnerabilities 
in isolation, failing to account for network topology, asset criticality, and attack path 
reachability. 
2. Lack of Explainability in AI Approaches: Graph Neural Networks and deep learning 
models provide predictions without forensic reasoning, making it difficult for security 
teams to validate and trust recommendations. 
3. High Computational Overhead: ML-based approaches require extensive training data 
and computational resources, limiting real-time applicability.

4. Absence of Unified Frameworks: Existing tools separate vulnerability scanning, risk

Chapter 2: Background and Literature Review 
 
2.1 Current Status at National and International Level 
Globally, cybersecurity research focuses on predictive analytics, attack graph modeling, and 
AI-driven risk assessment. International studies explore graph neural networks and 
probabilistic modeling for multi-stage attack prediction [6]. National initiatives emphasize 
compliance with standards such as NIST and ISO 27001. 
Despite these efforts, practical enterprise-ready solutions remain limited. Current trends 
include: 
• 
Attack Graph Research: Focus on modeling multi-stage attacks through graph 
representation 
• 
AI/ML Integration: Use of neural networks for pattern recognition and anomaly 
detection 
• 
Threat Intelligence Platforms: Integration of real-time threat feeds with vulnerability 
databases 
• 
Zero Trust Architecture: Emphasis on continuous verification and least privilege access 
• 
Compliance Automation: Tools for mapping security controls to regulatory frameworks 
 
2.2 Conventional Approaches 
Conventional vulnerability management systems perform vulnerability scanning using tools 
like Nessus, Qualys, or OpenVAS; assign CVSS severity scores; rank vulnerabilities 
independently without considering attack paths; recommend patching based on static severity 
levels; and generate reports for compliance and audit purposes. 
Key limitations include: 
• 
Absence of attack path prediction: No analysis of how vulnerabilities can be chained 
• 
Lack of vulnerability correlation: Each CVE is treated in isolation 
• 
No business-aware prioritization: Asset criticality is not factored into risk scores 
• 
Static analysis: No real-time threat correlation or dynamic risk updates 
• 
Limited forensic capability: Cannot reconstruct attacker movement paths 
• 
No simulation: Cannot model the impact of security controls before deployment

2.4 Research Gaps and Motivation for Proposed Work 
The following research gaps are identified from the literature review: 
1. Static attack graph models: Most approaches generate graphs once and do not update 
dynamically 
2. High computational complexity in ML/GNN approaches: Neural network models 
require extensive training and computational resources 
3. Lack of explainability: Deep learning approaches provide predictions without clear 
forensic reasoning 
4. No integrated forensic reasoning: Cannot trace attacker movement or reconstruct 
breach sequences 
5. No cost vs risk-based prioritization: Do not factor in attack cost relative to risk impact 
6. Limited enterprise scalability: Research prototypes often fail in production 
environments

Cyber Kill Chain methodology, and an integrated platform with real-time monitoring.

4.1 System Architecture 
The proposed architecture follows a four-layer design pattern for separation of concerns and 
scalability. 
4.1.1 Data Collection Layer 
Purpose: Ingestion and normalization of security-relevant datasets. Components include: 
• 
NVD Vulnerability Dataset: CSV file containing CVE IDs, CVSS scores, exploitability 
metrics, and impact scores 
• 
Enterprise Network Topology Dataset: JSON file defining nodes (assets) and edges 
(connections) with metadata 
• 
Asset Criticality Data: Criticality ratings (0–10 scale) assigned to each network asset 
based on business impact 
4.1.2 Vulnerability Correlation Engine 
Purpose: Maps CVEs to specific network assets and identifies exploitation dependencies. 
Assets are tagged with software/OS profiles (e.g., Apache, Windows Server, MySQL). CVE 
descriptions are matched against asset profiles, and exploitability scores determine edge 
weights. Chaining logic identifies prerequisites. 
4.1.3 Attack Graph Construction 
Purpose: Represents the network as a directed graph where nodes are assets and edges are 
connectivity/exploit paths. Nodes carry attributes including name, type, criticality, 
vulnerabilities, and average CVSS score. Edges carry protocol, source, target, and weight 
attributes. 
4.1.4 Attack Path Prediction Engine 
Purpose: Computes all possible attack paths from entry points to critical assets. Algorithms 
used: 
• 
All Simple Paths (BFS-based): Enumerates all non-cyclic paths — O(V+E) per path 
discovery 
• 
Shortest Path (Dijkstra): Finds minimum-cost path — O((V+E) log V) 
• 
Graph Traversal: Custom BFS/DFS for lateral movement simulation 
4.1.5 Risk Scoring Engine 
Purpose: Quantifies risk at node and path levels. 
Node Risk Formula: NodeRisk = (CVSS x Exploitability x Impact x AssetCriticality) / 
AttackCost 
Path Risk Formula: PathRisk = Sum(NodeRisk) x PathProbability, where PathProbability = 1 
/ (HopCount + 1)

4.1.6 Forensic Reasoning Module 
Purpose: Reconstructs attacker movement and identifies breach sequences using Cyber Kill 
Chain simulation (RECON, EXPLOIT, LATERAL MOVEMENT, EXFILTRATION) and 
heuristic detection rules for lateral movement, honeypot triggers, deep penetration, and zero-
day exploitation. 
4.1.7 Visualization Dashboard 
Purpose: Displays attack graph and risk rankings. Components include: Dashboard (posture 
overview), Network Explorer (3D force-directed graph), Vulnerability Lab (CVE database), 
Simulation Lab (mitigation analysis), Compliance Auditor, and Threat Hunter.

find_shortest_path(graph, source, target): Minimum-cost path using Dijkstra 
• 
get_neighbors(graph, node): Returns reachable nodes for lateral movement 
• 
serialize_graph(graph): Converts NetworkX graph to D3.js-compatible JSON

This research presents a scalable and explainable attack path prediction framework that 
addresses critical gaps in existing vulnerability management approaches. By correlating 
vulnerabilities using graph analytics, the system enhances enterprise cybersecurity posture and 
enables cost-aware decision-making.

Appendix B: Risk Formula Derivation 
Node Risk Formula: Risk = (CVSS x Exploitability x Impact x AssetCriticality) / AttackCost 
• 
CVSS: Industry-standard severity metric (0–10) 
• 
Exploitability: Ease of weaponization (0–10, from CVSS sub-score) 
• 
Impact: Damage potential (0–10, from CVSS sub-score) 
• 
AssetCriticality: Business impact (0–10, custom metric) 
• 
AttackCost: Defender's perspective difficulty (inversely related to exploitability) 
Normalization: NormalizedRisk = (RawRisk / TheoreticalMax) x 100. TheoreticalMax = (10 
x 10 x 10 x 10) / 1 = 10,000.
